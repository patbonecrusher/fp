Immutability

What makes "pure function" a guarantee instead of just a rule you have to remember.

What it is

A value is immutable when it can never be changed after it's created. If you want a "changed" version, you don't modify the original — you build a brand-new value with the change applied, and leave the original exactly as it was.

Concretely: array.push(x) mutates; [...array, x] doesn't. obj.key = x mutates; { ...obj, key: x } doesn't.

Why it matters

  • Makes purity real — a pure function can't mutate its arguments; immutable data structures enforce that instead of relying on discipline.
  • Safe snapshots — anything holding a reference to a value (an undo stack, a cache, a previous render) can trust it will never change out from under it.
  • Safe sharing — you can hand the same value to multiple functions, threads, or components without one's changes leaking into another's.
  • Easy change detection — "did this change?" becomes a reference check (oldValue !== newValue) instead of a deep comparison, which is exactly how libraries like React and Redux decide what to re-render.

Mutation's danger isn't the mutation itself — it's that anyone else holding a reference to that same value gets the change too, whether they expected it or not.

Before / after

✗ Mutable

function addTodoMutable(todos, todo) {
  todos.push(todo); // changes the array in place
  return todos;
}

✓ Immutable

function addTodoImmutable(todos, todo) {
  return [...todos, todo]; // new array
}

Watch it break

Building an undo history by pushing "snapshots" of a todo list into an array — using the mutable version, every "snapshot" is secretly the same array:

let todos = ["Buy milk"];
history.push(todos);
todos = addTodoMutable(todos, "Walk dog");
history.push(todos);
todos = addTodoMutable(todos, "Do laundry");
history.push(todos);

Actual output when you run the lesson script:

Mutable: 'undo' history (should show 3 different snapshots): [ [ 'Buy milk', 'Walk dog', 'Do laundry' ], [ 'Buy milk', 'Walk dog', 'Do laundry' ], [ 'Buy milk', 'Walk dog', 'Do laundry' ] ] Immutable: undo history (3 real, distinct snapshots): [ [ 'Buy milk' ], [ 'Buy milk', 'Walk dog' ], [ 'Buy milk', 'Walk dog', 'Do laundry' ] ] Earliest snapshot is untouched: true

The mutable history has three entries but they're all the same array — push changed it under everyone who was holding a reference to it, so "undo" has nothing distinct to go back to. The immutable version gives three genuinely different snapshots, because each step created a new array instead of changing the old one.

Related concepts

Pure Functions

Purity requires not mutating arguments; immutability is what turns that requirement into a guarantee.

Persistent Data Structures

Real-world immutable collections don't copy the whole structure on every change — they share unchanged parts internally to stay fast.

Referential Transparency

Relies on immutability: an expression can only be safely replaced by its value if that value can't later change.

Lens

A pattern for reading and "updating" deeply nested immutable data without manually spreading every level.
