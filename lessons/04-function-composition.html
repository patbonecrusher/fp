Function Composition

Build pipelines out of small, reusable functions instead of writing one big function per pipeline.

What it is

Think of an assembly line: a part goes into machine A, what comes out of A goes into machine B, what comes out of B goes into machine C. Nobody built one giant machine that does A, B, and C internally — three small, independent machines got chained together, in a specific order.

Function composition is that, for functions: compose(f, g)(x) just means f(g(x)) — run x through g, then run the result through f. Chain enough small functions together and you get a pipeline, without ever writing a function that does everything itself.

Two common helpers do this for a whole list of functions at once: pipe(f, g, h)(x) runs left-to-right (x → f → g → h), while compose(f, g, h)(x) runs right-to-left (x → h → g → f). Same idea, opposite reading direction — pick one convention and stick to it.

Why it matters

  • One source of truth per step — each small function (like "add tax") exists in exactly one place. Fix it there, and every pipeline built from it is fixed too.
  • Reusable building blocks — the same small functions can be assembled into different pipelines for different purposes, instead of copy-pasting the logic into each new "big" function.
  • Independently testable — you can unit-test addTax on its own, instead of only being able to test it buried inside a 40-line function.
  • Order becomes visible — pipe(applyDiscount, addTax) tells you the order at a glance; the same logic buried in a function body means reading every line to find out.

This only works cleanly when the functions being composed are pure. Compose functions with hidden side effects and the order they run in starts to matter in ways you can't see just by reading the pipeline.

Before / after

✗ Monolithic, duplicated logic

function wholesaleTotal(price) {
  const d = price * 0.9;
  return d * 1.08; // tax, copy 1
}

function retailTotal(price) {
  const t = price * 1.08; // tax, copy 2
  return t + 5;
}

✓ Composed from shared blocks

const applyDiscount = p => p * 0.9;
const addTax = p => p * 1.08; // tax, ONE copy
const addLateFee = p => p + 5;

const wholesaleTotal = pipe(applyDiscount, addTax);
const retailTotal = pipe(addTax, addLateFee);

Watch it break

The tax rate changes from 8% to 8.25%. In the monolithic version, that formula was copy-pasted into two different functions — someone fixes one and misses the other:

function wholesaleTotalFixed(price) {
  return (price * 0.9) * 1.0825; // fixed here
}
// retailTotal still has the old `* 1.08` — untouched, and easy to miss

Actual output when you run the lesson script:

Monolithic, tax rate 1.08: wholesale total for $100: 97.2 retail total for $100: 113 After fixing the tax rate in ONE of the two functions: wholesale total for $100: 97.425 retail total for $100: 113 <-- still using the OLD tax rate, silently Composed, tax rate 1.08: wholesale total for $100: 97.2 retail total for $100: 113 After fixing the tax rate ONCE, in the shared building block: wholesale total for $100: 97.425 retail total for $100: 113.25 <-- automatically consistent

In the composed version, addTax exists exactly once. Update it, and both wholesaleTotal and retailTotal — built by composing that same function — pick up the fix automatically. There's no second copy to forget.

Related concepts

Pure Functions

Composition is predictable specifically because each piece is pure — no hidden state sneaking between the steps.

Referential Transparency

Lets you freely inline a composed pipeline back into one expression, or extract part of one out, without changing behavior.

Currying

Curried functions (one argument at a time) are what make composing multi-argument functions into a clean pipeline actually practical.

Higher-Order Functions

pipe and compose are themselves higher-order functions: they take functions in and return a new function.

Point-Free Style

Composition taken further — defining a pipeline entirely in terms of the functions it chains, without ever naming the data flowing through it.
