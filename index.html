Functional Programming

One concept per lesson: a plain-language explanation, why it matters, a before/after code comparison, and a runnable TypeScript file.

Lessons fall into two kinds. Techniques are things you actively write — point at a line of code and that line is the technique happening (composing functions, currying, memoizing). Properties & tests are yes/no qualities you check on code you've already written (is it pure? immutable? referentially transparent?) — nobody "does" purity the way you "do" composition, but those properties are what license the techniques to be used safely.

Techniques — things you write

  1. Function Composition (Lesson 4)
    Build pipelines out of small, reusable functions instead of one big function per pipeline.
  2. Higher-Order Functions (Lesson 5)
    Separate the loop (mechanism) from what happens on each item (policy) — write the loop once, reuse it forever.
  3. Currying (Lesson 6)
    Give a function part of its input now, get back a specialized function waiting for the rest.
  4. Partial Application (next up — Lesson 7)

Properties & tests — things you check for

  1. Pure Functions (Lesson 1)
    Same input, same output, no side effects — the foundation everything else builds on.
  2. Immutability (Lesson 2)
    What makes "pure function" a guarantee instead of a rule you have to remember.
  3. Referential Transparency (Lesson 3)
    The payoff of purity and immutability: an expression and its value become interchangeable.
